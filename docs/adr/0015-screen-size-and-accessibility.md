# 0015. 화면 크기 3단계와 접근성

- 상태: 채택
- 날짜: 2026-11-20
- 관련 문제: P-22, P-23, P-24 ([01-legacy-analysis.md](../01-legacy-analysis.md))

## 맥락

기존 화면은 연세가 많은 사용자가 쓰기 어려웠다.

- 테마에 정의되지 않은 클래스(`text-md`, `gray-80` 등)를 여러 곳에서 썼고, Tailwind는 이를 경고 없이 무시했다. 비활성 버튼은 배경과 글자색이 같아 글자가 보이지 않았다 (P-22)
- 보조 글자색은 배경 대비 약 3.8:1로 WCAG AA 기준(4.5:1)에 못 미쳤고, 하단 메뉴 글자는 10px였다. 큰 글자 모드는 일부 글자 크기만 키우고 간격, 버튼, 아이콘은 그대로 두어 화면 균형이 깨졌다 (P-23)
- 로딩 상태가 없고, 불러오기에 실패하면 빈 화면이 보였다. 오류 안내는 대부분 `alert`였다 (P-24)

0단계에는 "화면 크기 3단계 구조와 선택"과 "공통 상태(로딩, 빈 화면, 오류)"가 있다. 나중에 넣으면 모든 화면을 다시 고쳐야 하므로 0단계에 둔다([02-domain-and-problem.md](../02-domain-and-problem.md) 6장). 사용자 흐름에서는 가입 중에 미리보기를 보며 작게, 보통, 크게 중 하나를 고르고, 내 정보에서 바꾼다([user-flows.md](../user-flows.md)). 2단계의 웹도 같은 시각 언어를 쓴다([ADR 0007](0007-client-platform.md)).

## 판단 기준

1. 단계를 바꾸면 글자, 간격, 버튼, 아이콘이 함께 바뀌고, 필요하면 배치도 바뀐다
2. 기기의 글자 크기 설정을 쓰는 사용자도 존중한다
3. 없는 토큰을 쓰거나 기준에 못 미치는 값을 넣으면 개발 중에 드러난다
4. 대비, 터치 영역 같은 접근성 기준을 모든 단계에서 지킨다
5. 2단계의 웹과 토큰을 공유한다

## 후보

### 단계를 적용하는 방식

#### A. 기기의 글자 크기 설정만 따른다

앱에 단계를 두지 않고, iOS와 Android의 글자 크기 설정에 맞춰 글자만 키운다. React Native의 `Text`는 기본으로 이 설정을 따른다("Specifies whether fonts should scale to respect Text Size accessibility settings.", `allowFontScaling`, https://reactnative.dev/docs/text).

- 장점: 플랫폼 표준이다. 따로 만들 것이 적다.
- 단점: 글자만 커지고 간격, 버튼, 아이콘은 그대로라 기존 큰 글자 모드와 같은 문제가 생긴다(기준 1). 기기 설정 화면을 찾아가야 해서 연세가 많은 사용자가 쓰기 어렵다.

#### B. 앱의 단계만 따르고 기기 설정은 무시한다

- 장점: 디자인한 대로만 보이므로 화면이 깨지지 않는다.
- 단점: 기기에서 글자를 키워 둔 사용자의 설정을 무시한다(기준 2).

#### C. 앱의 단계로 토큰 묶음을 고르고, 기기 글자 배율을 상한까지 곱한다

단계마다 글자, 간격, 버튼, 아이콘, 배치 값을 묶어 둔다. 글자에는 기기의 글자 크기 배율을 추가로 적용하되, `maxFontSizeMultiplier`로 상한을 둔다("Specifies the largest possible scale a font can reach when `allowFontScaling` is enabled.", https://reactnative.dev/docs/text).

- 장점: 단계를 바꾸면 화면 전체가 함께 바뀐다(기준 1). 기기 설정도 상한 안에서 반영한다(기준 2).
- 단점: 단계와 기기 배율이 겹치는 경우를 확인해야 한다. 상한값을 실기기로 정해야 한다.

### 토큰을 두는 방식

| 후보 | 특징 |
| --- | --- |
| CSS 변수, 스타일 클래스 (기존) | 없는 이름을 써도 조용히 무시된다(P-22). React Native에는 맞지 않는다 |
| TypeScript 객체와 타입 | 없는 토큰을 쓰면 타입 검사에서 실패한다. 앱과 웹이 같은 패키지를 쓴다 |
| 토큰 변환 도구 (Style Dictionary 등) | JSON 한 곳에서 여러 플랫폼 형식을 생성한다. 플랫폼이 둘뿐인 지금은 도구 관리가 더 크다 |

## 결정

**C(앱의 단계 + 상한을 둔 기기 글자 배율)를 채택하고, 토큰은 `packages/design-tokens`에 TypeScript로 둔다.**

### 토큰 구조

- **원시 값과 의미 토큰을 나눈다.** 원시 값은 색상표와 크기 눈금이다. 화면과 컴포넌트는 의미 토큰(`color.text.primary`, `space.md`, `font.body` 등)만 쓴다.
- **크기에 관한 의미 토큰은 단계마다 값을 가진다.** 글자, 줄 간격, 간격, 버튼 높이, 터치 영역, 아이콘, 배치(`layout.gridColumns` 등)다. 컴포넌트는 현재 단계의 값을 읽기만 하므로, 단계를 바꾸면 화면 전체가 함께 바뀐다.
- **색상 토큰은 단계와 관계없이 같다.** 대비는 모든 단계에서 같은 기준을 지킨다.
- **화면 코드에 색상, 간격 같은 값을 직접 쓰지 않는다.** 린트 규칙으로 막는다.
- 2단계의 웹은 같은 TypeScript 토큰에서 CSS 변수를 생성해 쓴다. 변환 방법은 웹을 만들 때 정한다.

구체적인 값은 디자인 단계에서 정한다. 아래는 구조를 보이기 위한 예시다.

```ts
// packages/design-tokens (예시, 값은 미정)
export const sizeTokens = {
  small:  { font: { body: 15 }, button: { height: 48 }, layout: { gridColumns: 3 } },
  medium: { font: { body: 17 }, button: { height: 52 }, layout: { gridColumns: 3 } },
  large:  { font: { body: 21 }, button: { height: 60 }, layout: { gridColumns: 2 } },
} as const;
```

### 접근성 기준

| 항목 | 기준 | 근거 |
| --- | --- | --- |
| 글자 대비 | 모든 글자 4.5:1 이상. 큰 글자(18pt, 굵게 14pt 이상)는 3:1 이상 | WCAG 2.2 1.4.3 (AA), https://www.w3.org/TR/WCAG22/ |
| 비활성 상태 글자 | 3:1 이상. WCAG는 비활성 컴포넌트를 대비 기준에서 빼지만("part of an inactive user interface component ... have no contrast requirement"), 기존 비활성 버튼의 글자가 보이지 않았던 문제(P-22)가 있어 예외로 두지 않는다 | P-22 |
| 터치 영역 | 모든 단계에서 48×48 이상. 보이는 크기가 작아도 누를 수 있는 영역은 이 이상으로 둔다 | Android 권장 "at least 48dpx48dp" (https://developer.android.com/guide/topics/ui/accessibility/apps). WCAG 2.2 2.5.8(AA)의 최소 24×24보다 크게 잡는다 |
| 글자 크기 하한 | 어떤 단계, 어떤 글자도 하한 아래로 내려가지 않는다. 하한값은 디자인 단계에서 정한다 | P-23 (하단 메뉴 10px) |
| 기기 글자 배율 | 크게 단계에 기기 배율을 곱해도 화면이 깨지지 않는 값을 `maxFontSizeMultiplier` 상한으로 둔다. 상한값은 실기기에서 정한다 | 기준 2 |
| 스크린 리더 | 아이콘만 있는 버튼에도 읽을 이름을 붙인다. 웹은 문서 언어를 `ko`로 둔다 | P-23 (문서 언어 `en`) |

Apple의 Human Interface Guidelines에 있는 최소 터치 영역도 확인하려 했지만, 페이지 본문을 가져오지 못해 근거로 쓰지 않았다. 48×48은 Android 권장값을 따른 것이다.

### 단계의 선택과 저장

- 가입 중에 미리보기를 보며 고르고, 내 정보에서 바꾼다.
- 고른 단계는 기기에 저장하고 계정 설정에도 저장한다. 다른 기기에서 로그인해도 유지된다.
- 로그인 전 화면은 기기에 저장된 단계를 쓰고, 없으면 보통으로 시작한다.

### 공통 컴포넌트와 상태

- 화면은 공통 컴포넌트를 조합해 만든다. 공통 컴포넌트는 의미 토큰만 쓴다.
- 로딩, 빈 화면, 오류, 분석 중 상태를 공통 컴포넌트로 통일한다(P-24).
- 오류 상태에는 항상 다음 행동(다시 시도, 돌아가기)을 함께 보여준다. `alert`만 띄우고 끝내지 않는다.

### 버린 후보

- A는 기존 큰 글자 모드와 같은 문제(글자만 커짐)를 다시 만든다.
- B는 기기 설정으로 글자를 키워 둔 사용자를 무시한다.
- 토큰 변환 도구는 플랫폼이 더 늘어나면 다시 검토한다.

## 결과

- 얻는 것: 단계를 바꾸면 화면 전체가 함께 바뀐다. 없는 토큰과 기준에 못 미치는 값은 개발 중에 드러난다. 앱과 웹이 같은 토큰을 쓴다.
- 잃는 것: 모든 화면을 공통 컴포넌트와 의미 토큰으로 만들어야 한다. 단계 세 개와 기기 배율의 조합을 확인해야 한다.
- 후속 작업:
  - 디자인 단계: 단계별 토큰 값, 글자 크기 하한
  - 구현 초기: `maxFontSizeMultiplier` 상한을 실기기에서 정한다
  - 공통 컴포넌트를 세 단계로 한눈에 확인할 도구(Storybook 등)는 구현할 때 고른다
  - 크게 단계 세부 조정은 1단계

## 검증

assertion:

- 앱 코드에서 정의되지 않은 토큰을 쓰면 타입 검사에서 실패한다.
- 화면 코드에 색상 값이나 간격 숫자를 직접 쓰면 린트에서 실패한다.
- 토큰에 정의된 모든 글자색과 배경색 조합이 대비 기준(4.5:1, 큰 글자 3:1, 비활성 3:1)을 넘는다. 토큰 테스트로 계산해 확인한다.
- 모든 단계의 터치 영역 토큰이 48 이상이고, 글자 크기 토큰이 하한 이상이다.
- 단계를 바꾸면 앱을 다시 시작하지 않아도 글자, 간격, 버튼 크기가 함께 바뀐다.
- 다른 기기에서 로그인하면 마지막으로 고른 단계가 적용된다.
- 불러오기에 실패한 화면은 빈 화면이 아니라 오류 상태와 다시 시도 버튼을 보여준다.

실기기 확인(자동화하지 않음):

- 크게 단계에서 기기 글자 크기를 가장 크게 해도 핵심 화면(홈, 촬영, 답변 상세, 보관함)의 글자와 버튼이 잘리거나 겹치지 않는다.
