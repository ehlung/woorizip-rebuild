# 0003. 영상 형식과 업로드 경로

- 상태: 채택
- 날짜: 2026-11-20
- 관련 문제: P-05, P-25 ([01-legacy-analysis.md](../01-legacy-analysis.md))

## 맥락

기존에는 영상이 서버를 거쳐 올라갔다. 앱이 영상을 BE에 multipart로 보내면, BE가 S3에 저장하고 같은 영상을 다시 AI 서버로 보냈다. 같은 영상이 서버를 세 번 지나갔고, 영상을 받는 동안 BE의 요청 스레드가 묶였으며, 중간에 끊기면 처음부터 다시 보내야 했다(P-05). 녹화 형식은 webm으로 고정되어 일부 기기에서 실패할 수 있었다(P-25).

영상은 앱에서 찍고 분석은 AI 워커가 한다. BE가 영상 파일을 받아 넘길 이유가 없다. BE는 누가 어디에 올려도 되는지와 답변의 상태만 책임지면 된다.

[ADR 0002](0002-async-analysis.md)에서 AI 워커가 BE에서 분석 작업을 가져가기로 했으므로, 워커가 영상을 어떻게 받는지도 함께 정한다.

## 판단 기준

1. BE가 영상 파일을 다루지 않는다
2. 업로드 중 끊겼을 때 다시 올리는 비용이 사용자에게 감당할 만하다
3. 업로드 권한이 정해진 사용자, 정해진 파일 하나로 제한된다
4. AI 서버가 저장소 접근 키를 갖지 않는다
5. 1인 개발로 구현과 운영을 감당할 수 있다
6. 운영하면서 업로드 실패가 잦다고 확인되면 더 견고한 방식으로 옮길 수 있다

## 영상 형식

| 항목 | 값 | 이유 |
| --- | --- | --- |
| 해상도 | 720p | 얼굴과 목소리가 중심인 영상이라 휴대폰 화면에서 충분하다. 실제 기기로 찍어 확인했다 |
| 코덱과 컨테이너 | H.264, mp4 | iOS, Android, 웹에서 모두 재생된다. 아이폰 기본값인 HEVC는 일부 Android와 웹에서 재생되지 않는다 |
| 프레임 | 30fps | 휴대폰 영상의 기본값이다. 말하는 얼굴 위주라 60fps가 필요 없다 |
| 최대 길이 | 3분 | 근거가 있는 값이 아니라 가정이다. 1차 피드백에서 답변 길이 분포와 제한에 걸린 비율로 확인한다 |
| 크기 목표 | 3분 기준 100MB 미만 | 아래 업로드 방식의 기준. 비트레이트 상한은 구현할 때 실제 파일 크기를 재서 정한다 |

## 후보

### A. 서버 경유 (기존)

앱이 영상을 BE에 보내고, BE가 S3에 저장한다.

- 장점: 구현이 단순하다.
- 단점: BE가 영상 트래픽을 모두 감당한다(기준 1). 끊기면 처음부터 다시 보낸다.

### B. presigned URL로 직접 업로드

BE가 로그인과 가족 권한을 확인한 뒤, 정해진 파일 하나에 일정 시간 동안만 올릴 수 있는 presigned URL을 발급한다. 앱은 S3에 직접 올리고, 다 올리면 BE에 완료를 알린다.

- 장점: BE가 영상 파일을 다루지 않는다(기준 1). 업로드 진행률을 보여주기 쉽다. 구현이 비교적 단순하다(기준 5).
- 단점: 끊기면 처음부터 다시 올린다(기준 2). 앱이 완료를 알리지 못하면 주인 없는 파일이 S3에 남는다.

### C. S3 멀티파트 업로드

영상을 여러 조각으로 나눠 각각 올리고, 끊기면 실패한 조각만 다시 올린다.

- 장점: 약한 모바일 망에서도 이어 올릴 수 있다(기준 2).
- 단점: 업로드 시작, 조각별 주소 발급, 완료, 실패 시 정리까지 흐름이 늘어난다(기준 5).

### D. 영상 전문 서비스 (Mux, Cloudflare Stream 등)

업로드, 형식 변환, 재생을 외부 서비스에 맡기고, 처리가 끝나면 알림을 받는다.

- 장점: 형식 변환과 재생 최적화를 직접 만들지 않아도 된다(기준 5).
- 단점: AI 분석에는 원본 파일이 필요해 서비스에서 다시 내려받아야 한다. 가족 영상을 맡기는 외부 업체가 하나 더 늘어나, 개인정보 처리방침에 수탁자로 공개해야 한다. 서비스에 종속된다.

요금(2026-11-20 각 공식 페이지 기준):

- Cloudflare Stream: 저장 1,000분당 월 $5(선불), 재생 1,000분당 $1, 업로드와 인코딩은 무료
- Mux: 저장 분당 월 $0.003, 재생은 월 100,000분까지 무료, 월 $20 사용 크레딧

지인 테스트 규모에서는 D도 월 몇 달러 수준이라 비용은 판단 기준이 되지 않는다.

## 결정

**영상은 720p, H.264 mp4, 30fps, 최대 3분으로 찍고, B(presigned URL 직접 업로드)로 시작한다. 업로드 API는 C로 바꿀 수 있는 모양으로 둔다.**

- A는 기준 1을 만족하지 못한다.
- AWS는 100MB 이상인 객체에 멀티파트 업로드를 권장한다("It's a best practice to use multipart upload for objects that are 100 MB or larger", Amazon S3 User Guide). 영상 크기를 100MB 아래로 두면 B가 이 기준에 맞는다.
- C는 기준 2에서 가장 낫지만, 지금은 업로드 실패가 얼마나 잦을지 알 수 없다. 연세가 많은 사용자가 집 와이파이로 올릴지 모바일 데이터로 올릴지에 달려 있다. 1차 피드백에서 업로드 실패율을 재서, 실패가 잦으면 C로 옮긴다.
- D는 비용이 아니라 원본 파일 재다운로드, 수탁자 추가, 서비스 종속 때문에 지금은 쓰지 않는다. 서버에서 형식을 변환하는 단계가 운영 부담이 되면 다시 검토한다.

### 동작 방식

```
1. 앱: BE에 업로드 세션 요청
2. BE: 로그인과 가족 권한 확인 → presigned URL 발급 (파일 하나, 업로드만, 15분, 크기·형식 조건)
3. 앱: S3에 직접 업로드 (진행률 표시)
4. 앱: BE에 업로드 완료 알림
5. BE: S3에서 파일 존재, 크기, 형식 확인 → 답변(분석 중)과 분석 작업 저장 (ADR 0002)
6. AI 워커: 작업을 가져갈 때 BE가 함께 발급한 presigned URL(읽기 전용, 15분)로 S3에서 직접 내려받음
```

- **업로드 세션**: BE가 업로드 한 건을 세션으로 발급하고, 그 안에 업로드 주소를 담는다. 지금은 주소가 하나(B)지만, C로 옮기면 조각별 주소 여러 개를 담는다. 앱과 BE의 약속은 그대로 두고 세션 안의 내용만 바뀐다.
- **크기와 형식 조건**: 크기 범위를 서명에 확실히 넣으려면 S3의 POST 방식 업로드(조건을 정책으로 거는 방식)를 쓴다.
- **완료 알림의 중복**: 앱이 완료 알림을 다시 보내도 답변이 하나만 생기도록 업로드 세션 단위로 중복을 막는다. 자세한 처리는 [ADR 0004](0004-failure-and-retry.md)에서 정한다.
- **완료를 알리지 못한 파일**: 업로드 직후 앱이 꺼지는 등으로 완료 알림이 오지 않은 파일은 S3 수명 주기 규칙으로 일정 기간 뒤 삭제한다.
- **완료 확인 방식**: S3가 업로드 완료를 직접 알려주는 이벤트 알림도 있지만, 받는 쪽 큐나 함수, 권한, 중복 처리가 추가된다. 지금 규모에서는 비용 차이가 없으므로(SQS와 Lambda 모두 월 100만 건 무료), 구성이 단순한 앱 알림 방식을 쓴다.
- **저장소**: 버킷은 비공개로 두고, 읽기도 presigned URL로만 한다.

## 결과

- 얻는 것:
  - BE가 영상 파일을 다루지 않는다.
  - 업로드 권한이 파일 하나, 15분으로 제한되고, AI 서버는 저장소 키 없이 영상을 읽는다.
  - 영상이 3분 기준 100MB 미만이라 AWS 권장 기준에 맞는다.
- 잃는 것:
  - 업로드가 끊기면 처음부터 다시 올린다.
  - 업로드 직후 앱이 꺼지면, 사용자가 다시 열기 전까지 답변이 만들어지지 않는다.
- 후속 작업:
  - 0004: 업로드 완료 알림의 중복 처리, 업로드 실패 시 앱의 재시도 흐름
  - 0007: 업로드 중 앱이 백그라운드로 갈 때 업로드를 이어 가는 방법
  - 구현 시: 720p 3분 영상의 실제 크기를 재고 비트레이트 상한을 정한다

## 검증

assertion:

- 로그인하지 않았거나 가족이 아닌 사용자에게는 업로드 세션을 발급하지 않는다.
- 발급된 주소로는 지정된 파일 외의 경로, 제한보다 큰 파일, mp4가 아닌 파일을 올릴 수 없다.
- 만료된 주소로는 올릴 수 없다.
- 같은 업로드 세션으로 완료 알림을 여러 번 보내도 답변은 하나만 생긴다.
- AI 워커는 저장소 키 없이 발급받은 읽기 주소로만 영상을 내려받는다.
- 720p, 3분 영상의 크기가 100MB 미만이다.

지표(1차 피드백):

- 업로드 실패율과 재시도 횟수. 실패가 잦으면 C로 옮긴다. 기준값은 [04-evaluation.md](../04-evaluation.md)에서 정한다
- 업로드 소요 시간
- 답변 길이 분포, 3분 제한에 걸린 비율
