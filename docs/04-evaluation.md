# 평가 기준

리빌드가 문제를 해결했는지, 결정이 맞았는지를 무엇으로 판단하는지 정리한다.

| 구분 | 무엇인가 | 판정 |
| --- | --- | --- |
| assertion | 반드시 성립해야 하는 동작 | 참/거짓. 자동 테스트로 확인한다 |
| rubric | 정답이 하나가 아닌 결과의 품질 기준 | 점수. 사람이 채점표로 평가한다 |
| 운영 지표 | 실제 사용에서 가정과 결정을 확인하는 수치 | 기준값과 비교한다 |
| 기준선 | 기존 프로젝트의 상태 | 개선 전후 비교의 출발점 |

assertion의 출처는 ADR이고, 운영 지표의 출처는 [02-domain-and-problem.md](02-domain-and-problem.md) 4장의 가정과 ADR의 검증 항목이다. ADR을 새로 채택하면 이 문서에 assertion과 지표를 추가한다.

## 1. 기준선

기존 서버와 운영 데이터가 남아 있지 않아, 기준선은 코드와 git 이력에서 확인할 수 있는 사실로 잡는다. 근거는 [01-legacy-analysis.md](01-legacy-analysis.md)의 문제 번호다.

| 항목 | 기존 프로젝트 | 근거 |
| --- | --- | --- |
| 자동 테스트 | FE 0개, BE 1개(`contextLoads`), AI 0개. CI는 테스트를 건너뜀 | 01의 1장, 4장 |
| 업로드 응답 시간 | AI 분석이 끝날 때까지 응답하지 않음. 타임아웃 없음 | P-05 |
| AI 단계 실패 시 | 업로드 전체 실패, 답변 생성 안 됨 | P-07 |
| 실패 후 재시도 | 없음 | P-08 |
| 지난 주차 다시 보기 | 동작하지 않음 | P-16 |
| 다른 가족 데이터 접근 | ID로 단건 조회 시 가족 확인 없음 | P-13 |
| 전체 서비스 로컬 실행 | 한 번에 띄우는 방법 없음, DB 스키마 없음 | P-03, P-04 |
| 저장소에 커밋된 비밀값 | AWS 키, JWT 서명 키 등 | 01의 4장 |

실행해서 재야 하는 기준선(업로드 응답 시간 등)은 리빌드 환경에서 기존 방식(동기 처리)을 재현해 측정한다. 측정하면 이 표에 추가한다.

## 3. rubric (초안)

AI 결과는 정답이 하나가 아니므로 rubric으로 채점한다. 평가셋과 rubric은 AI 제공자 선택([ADR 0012](adr/0012-ai-provider.md))과 이후 모델·프롬프트 변경에 같이 쓴다. 채점 방식과 합격 기준은 ADR 0013에서 확정한다.

### 평가셋

- 동의를 받은 가족 답변 영상으로 구성한다.
- 다음 경우를 고르게 포함한다: 연세가 많은 화자, 사투리, 배경 소음, 여러 사람이 함께 나오는 영상, 말이 거의 없는 영상, 3분을 꽉 채운 영상
- 영상마다 사람이 직접 받아 적은 정답 transcript를 만든다.

### STT

rubric 대신 수치로 평가한다.

| 지표 | 정의 |
| --- | --- |
| 문자 오류율(CER) | 정답 transcript와 비교해 틀린 글자의 비율 |
| 무음 구간의 없는 말 | 말이 없는 구간에서 만들어 낸 문장이 있는지 |
| 처리 시간 | 3분 오디오 기준 |

### 요약

| 기준 | 0점 | 1점 | 2점 |
| --- | --- | --- | --- |
| 사실성 | 말하지 않은 내용을 지어냄 | 일부를 왜곡하거나 중요한 내용을 빠뜨림 | 모두 실제로 말한 내용이고 핵심이 담김 |
| 간결성 | 세 문장을 넘기거나 핵심이 흐림 | 핵심은 있지만 군더더기가 있음 | 두 문장 안에 핵심이 담김 |
| 말투 | 보고서체이거나 화자를 평가함 | 어색한 표현이 있음 | 가족이 읽기 편하고 화자를 존중함 |

사실성은 다른 기준보다 우선한다. 사실성이 0점인 결과는 다른 점수와 관계없이 불합격이다.

### 제목

| 기준 | 0점 | 1점 | 2점 |
| --- | --- | --- | --- |
| 내용 반영 | 답변 내용과 무관함 | 질문을 반복하는 수준 | 답변의 핵심을 짧게 담음 |
| 길이 | 화면 한 줄을 넘김 | | 화면 한 줄 안에 들어감 |

### 썸네일

| 기준 | 0점 | 1점 | 2점 |
| --- | --- | --- | --- |
| 얼굴 | 얼굴이 없거나 가려짐 | 얼굴이 있지만 흐리거나 잘림 | 얼굴이 선명하게 보임 |
| 표정 | 눈을 감았거나 말하는 도중의 어색한 순간 | 무표정 | 자연스러운 표정 |

점수와 함께, 사람이 고른 대표 장면과 AI가 고른 장면이 얼마나 일치하는지도 본다.

## 4. 운영 지표

1차, 2차 피드백에서 확인한다. 기준값은 구현하면서 실측한 값을 보고 정한다. 아래 값은 출발점으로 둔 초안이다.

### 가정 확인 ([02-domain-and-problem.md](02-domain-and-problem.md) 4장)

| 지표 | 확인하는 가정 | 시점 |
| --- | --- | --- |
| 연령대별 첫 답변 완료 여부, 촬영 시작 대비 업로드 완료 비율, 도움 요청 횟수 | 연세가 많은 가족도 혼자 촬영과 업로드를 마칠 수 있다 | 1차 |
| AI 제목·요약을 수정 없이 쓰는 비율, 수정 정도 | AI 정리가 기록 부담을 줄인다 | 1차 |
| 질문별 답변률, 주차별 답변률 추이 | 가족은 매주 질문에 영상으로 답한다 | 1차, 2차 |
| 답변 길이 분포, 3분 제한에 걸린 비율 | 3분이면 하고 싶은 이야기를 충분히 담는다 | 1차 |
| 반응을 받은 사용자와 받지 못한 사용자의 다음 주 답변률 | 반응이 다음 답변의 동기가 된다 | 2차 |
| 지난 주차 보관함 열람 빈도 | 쌓인 기록을 다시 본다 | 2차 |

### 결정 확인 (ADR)

| 지표 | 확인하는 결정 | 기준값 (초안) |
| --- | --- | --- |
| 업로드 응답 시간 | 0002: 업로드가 분석 시간과 무관하다 | 영상 업로드 완료 후 1초 이내 응답 |
| 업로드 완료부터 분석 시작까지의 지연 | 0002: long polling으로 바로 시작한다 | 10초 이내 |
| 분석 소요 시간 (영상 길이별) | 0002, 0012 | 3분 영상 5분 이내 |
| 분석 1건당 비용 (STT, 요약) | 0012 | 기준값 없음. 제공자 비교와 비용 추이를 본다 |
| 업로드 실패율, 재시도 횟수, 업로드 소요 시간 | 0003: presigned URL 단일 업로드로 충분하다 | 재시도 후에도 실패하는 비율이 5%를 넘으면 멀티파트 업로드 검토 |
| 분석 성공률, 재시도 후 성공률, 실패 종류별 비율 | 0004: 재시도 횟수와 간격 | 재시도 후 성공률 99% 이상 |
| 기본값으로 공개된 답변 중 작성자가 직접 고친 비율 | 0004: 실패해도 답변을 남긴다 | 기준값 없음. 실패 알림이 효과가 있는지 본다 |
| 답변당 다시 찍기 횟수 분포 | 0004: 하루 20회 제한 | 제한에 걸린 사용자가 있으면 제한값 재검토 |

### 측정 방법

- 앱과 서버에 이벤트를 기록한다(업로드 시작·완료·실패, 분석 시작·완료·실패, 다시 찍기, 보관함 열람 등).
- 이벤트에는 영상, transcript, 요약 같은 답변 내용을 남기지 않는다. 사용자와 가족은 내부 ID로만 기록한다.
- 도움 요청 횟수처럼 이벤트로 잴 수 없는 항목은 1차 피드백 중 직접 기록한다.
