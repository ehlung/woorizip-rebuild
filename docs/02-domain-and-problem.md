# 도메인과 문제 정의

이 문서는 우리.zip이 어떤 문제를 풀려는 서비스인지, 어떤 조건에서 만드는지, 무엇을 근거로 기능 범위를 정했는지 정리한다.

## 1. 도메인

### 배경

일자리가 수도권에 몰리고, 같은 지역에 살더라도 가정을 꾸리면 분가하면서 가족은 여러 가구로 나뉘어 산다. 따로 살면 일상에 쫓겨 연락이 뜸해지고, 본가가 멀수록 직접 찾아가기도 어렵다. 조부모와 부모에게서 "얼굴 보기 어렵다"는 말을 자주 듣게 된다.

연세가 많은 가족이 세상을 떠난 뒤에야 "연락을 더 할걸", "사진이라도 많이 찍어 둘걸" 하고 후회하는 경우가 많다. 남은 것은 몇 장의 사진뿐이고, 그 사람의 목소리나 말투, 살아온 이야기는 기록으로 남아 있지 않다.

### 서비스 정의

> **우리.zip은 AI를 활용해 떨어져 사는 가족의 소통을 돕고, 그 기록을 다시 꺼내 볼 수 있게 한다.**

- **주간 질문**은 가족이 다양한 이야기를 꺼낼 수 있도록 주제를 정해 주는 가이드다.
- **영상 답변**은 얼굴과 목소리를 함께 기록한다.
- **AI**는 영상에서 제목, 요약, 대표 장면을 만들어 기록을 정리하는 부담을 덜어 준다.
- **보관함**은 쌓인 기록을 주차별로 모아 다시 볼 수 있게 한다.

글을 직접 써서 기록하는 서비스는 이미 많다. 우리.zip의 차별점은 영상으로 남긴 기록을 AI가 정리해 준다는 점이다.

### 사용자

- 따로 사는 가족 구성원. 부모와 조부모, 성인이 된 자녀와 손주를 포함한다.
- 연세가 많은 가족도 직접 답변을 찍고 가족의 답변을 볼 수 있어야 한다. 화면 크기를 3단계로 나누고 글자, 간격, 버튼을 함께 키우는 기능은 이 사용자를 위한 것이다.

### 기존 프로젝트와 달라진 조건

기존 프로젝트는 졸업 프로젝트였고, "얼굴·동작 인식 AI를 활용한다"는 주제 조건이 있었다. 얼굴 가이드, 얼굴 기반 썸네일 선택, 반려동물 인식 같은 기능은 이 조건에서 출발했다. 리빌드에는 이 조건이 없으므로, 각 기능은 사용자 니즈를 기준으로 다시 판단한다.

## 3. 니즈

니즈마다 근거와 확신도를 적는다. 확신도가 낮은 니즈는 4장의 가정으로 다루고, 운영하면서 확인한다.

| ID | 니즈 | 근거 | 확신도 |
| --- | --- | --- | --- |
| N1 | 떨어져 사는 가족은 서로의 일상을 알기 어렵다 | 개발자와 팀원의 경험, 조부모·부모에게서 자주 듣는 말 | 중간 |
| N2 | 가족을 잃은 뒤 기록이 남아 있지 않아 후회하는 경우가 많다 | 주변에서 본 사례 | 중간 |
| N3 | 사진이나 글보다 얼굴과 목소리가 담긴 영상이 더 의미 있는 기록이다 | 없음 | 낮음 |
| N4 | 무엇을 이야기할지 정해 주면 기록을 시작하기 쉽다 | 없음 | 낮음 |
| N5 | 기록을 직접 정리하는 부담이 기록을 끊기게 한다. AI가 정리하면 부담이 줄어든다 | 없음. 서비스 차별점의 전제 | 낮음 |
| N6 | 연세가 많은 가족도 직접 영상을 찍어 올릴 수 있다 | 없음 | 낮음 |
| N7 | 연세가 많은 사용자는 작은 글자와 낮은 대비를 읽기 어렵고, 작은 버튼을 누르기 어렵다 | 노안 등 연령에 따른 시력 변화, 웹 접근성 기준(WCAG) | 높음 |
| N8 | 쌓인 기록을 나중에 다시 찾아볼 수 있어야 한다 | 서비스 목적(후회하지 않을 기록)에서 도출 | 중간 |
| N9 | 가족의 반응이 다음 답변을 남기는 동기가 된다 | 없음 | 낮음 |

## 4. 가정과 확인 방법

확신도가 낮은 니즈를 가정으로 두고, 가족과 지인 대상 운영에서 확인한다. 지표의 정의와 기준값은 [04-evaluation.md](04-evaluation.md)에서 정한다.

| 가정 | 관련 니즈 | 확인 방법 | 확인 시점 |
| --- | --- | --- | --- |
| 연세가 많은 가족도 혼자 촬영과 업로드를 마칠 수 있다 | N6, N7 | 연령대별 첫 답변 완료 여부, 촬영 시작 대비 업로드 완료 비율, 도움을 요청한 횟수(운영 중 직접 기록) | 1차. 구현 전에 화면 프로토타입으로도 미리 확인한다 |
| AI 정리가 기록 부담을 줄인다 | N5 | AI 제목·요약을 수정 없이 쓰는 비율, 수정한 경우 수정 정도 | 1차 |
| 가족은 매주 질문에 영상으로 답한다 | N3, N4 | 질문별 답변률, 주차별 답변률 추이 | 1차에서 첫 반응, 2차에서 추이 |
| 반응이 다음 답변의 동기가 된다 | N9 | 반응을 받은 사용자와 받지 못한 사용자의 다음 주 답변률 비교 | 2차. 여러 주의 데이터가 필요하다 |
| 쌓인 기록을 다시 본다 | N8 | 지난 주차 보관함 열람 빈도 | 2차. 기록이 쌓여야 확인할 수 있다 |

## 5. 문제 정의

### 사용자 문제

떨어져 사는 가족이 서로의 일상을 부담 없이 나누고, 그 기록을 나중에 다시 꺼내 볼 수 있는 방법이 마땅치 않다. 메신저 대화와 사진은 쌓이기만 할 뿐 정리되지 않고, 따로 기록을 남기려면 무엇을 남길지 정하고 정리하는 수고가 든다.

### 기존 구현의 문제

기존 프로젝트는 이 문제를 풀기 위한 기능을 넓게 만들었지만, 실제 가족이 쓸 수 있는 상태가 아니었다. 자세한 근거는 [01-legacy-analysis.md](01-legacy-analysis.md)에 있고, 괄호 안의 번호는 그 문서의 문제 번호다.

- **기록을 잃을 수 있었다.** 업로드 요청 안에서 AI 분석을 끝까지 기다렸고, 분석이 실패하면 업로드 전체가 실패했다. 실패하면 영상을 처음부터 다시 올려야 했다. (P-05, P-07, P-08, P-10)
- **기록이 가족 밖으로 샐 수 있었다.** 다른 가족의 답변을 ID로 조회할 수 있었고, 서명 키와 접근 키가 공개 저장소에 있었다. (P-12, P-13, 01의 4장)
- **쌓인 기록을 다시 볼 수 없었다.** 지난 주차를 선택해도 이번 주 내용이 나왔다. (P-16)
- **연세가 많은 가족이 쓰기 어려웠다.** 대비와 글자 크기가 부족했고, 실패하면 막다른 화면에 갇혔다. (P-10, P-23, P-24)
- **실행하고 검증할 방법이 없었다.** 세 서비스를 한 번에 띄울 수 없었고, 테스트가 거의 없었다. (P-03, P-04, 01의 4장)
- **핵심보다 기능 수가 앞섰다.** 화면은 47개였지만 상당수가 미완성이었고, 핵심 흐름은 실패에 대비되어 있지 않았다. (01의 5장)

### 리빌드의 문제 정의

> 실제 가족이 매주 쓰는 서비스로 운영하려면, 핵심 흐름(질문 → 영상 답변 → AI 정리 → 가족이 보기 → 다시 보기)이 다음을 만족해야 한다.
>
> 1. 어느 단계가 실패해도 기록을 잃지 않는다.
> 2. 기록은 가족 안에서만 보인다.
> 3. 연세가 많은 가족도 혼자 쓸 수 있다.
> 4. 언제든 같은 방법으로 실행하고 검증할 수 있다.
>
> 기존 구현은 네 가지를 모두 만족하지 못했다. 리빌드는 범위를 핵심 흐름으로 좁히고, 이 네 가지를 먼저 만족시킨다.
